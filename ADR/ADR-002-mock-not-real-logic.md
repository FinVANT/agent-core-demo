# ADR-002: 실제 로직 대신 결정론적 목업을 쓴다

- Status: Accepted

## Context

공개 데모를 진짜처럼 보이게 하려면 두 가지 방법이 있다 — (1) 실제 백엔드를 읽기 전용으로
축소해서 붙이거나, (2) API 계약만 같은 가짜 백엔드를 새로 짠다. (1)은 실제 라우팅 판단·
프롬프트·검증 게이트 코드가 그대로 배포되므로 제품의 핵심 노하우가 공개된다.

## Decision

(2)를 택했다. 컴포넌트 분해, 상태 배정, 파일 개수 등은 전부 `lib/hash.js`의 결정론적
해시로 계산한다 — 진짜 LLM도 안 부르고, 진짜 판단 로직도 없다. `BRD.md`에 무엇이 진짜고
무엇이 mock인지 표로 명시했다.

## Consequences

- 장점: 이 저장소를 통째로 공개해도 실제 제품이 "어떤 요구사항을 BE로, 어떤 걸 FE로 보내는지"
  판단하는 알고리즘은 전혀 드러나지 않는다.
- 장점: LLM 호출 비용이 0이다 — 방문자가 아무리 눌러도 API 요금이 나가지 않는다.
- 단점: "총괄이 실제로 얼마나 똑똑한가"는 이 데모로 보여줄 수 없다. 그건 의도된 제약이다 —
  그 부분을 보여줘야 할 때는 비공개BE 쪽 문서(ERD/BRD/ADR)를 근거로 설명한다(`BRD.md` 참고).
